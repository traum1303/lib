## Установка

1.
    - `mkdir {dir_name}`
    - `cd {dir_name}`
    - `git init`
    - `git remote add origin https://github.com/traum1303/lib.git`
    - `git pull origin main`
2.

```bash
docker compose -f docker-compose-dev.yml -p lib up -d

docker exec lib_backend bash -c "composer install"

docker exec lib_backend bash -c "php artisan app:setup" 
```

###### !!Ахтунг!!! - у вас может быть другое имя контейнера если вы работаете на убунту: не через подчеркивание , а через дефис (lib-backend). проверить в докере

Команда
>docker exec lib_backend bash -c "php artisan app:setup"  

внутри контейнера 
1. копирует .env файл из .env.example
2. запускает миграции
3. ранит сидер, 
4. линкует сторадж,
5. устанавливает зависимости npm
6. собирает npm билд 

### Альтернативная установка согласно очереди 

0. вход в контейнер `docker exec -it lib_backend bash` . !! СЛЕДУЮЩИЕ КОМАНДЫ ОБЯЗАТЕЛЬНО НУЖНО ЗАПУСКАТЬ ВНУТРИ КОТЕЙНЕРА!!
1. `cp .env.example .env`
2. `php artisan migrate`
3. `php artisan db:seed`
4. `php artisan storage:link`
5. `npm install`
6. `npm run build`

#### Несколько комментариев к заданию

1. Можно было в реализации использовать alpine.js + livewire. Обычно это упрощает разработку для такого типа приложения, но я сознательно их не использовал согласно ТЗ
2. Из интересных фич/костылей
   - кое-где использовал дтошки для рендера результатов поиска моделей
   - добавил индексы по частым полям поиска по типу book_isbn. Насколько мне подсказал гугл и здравый смысл, это поле уникальное для каждой книги, но формат везде разный, воспользовался дефолтным фейкером
   - лочится количество книг при попытке выдачи (изменении количества доступных экземпляров)
   - есть несколько ajax запросов на jquery. рендер происходит на бекенде, не стал использовать с json форматом как по аналогии с ресурсом как для АПИ и отдельного фронта
   - пагинацию в качестве примера использовал стандартную, но можно было курсорную с бесконечным скроллом
   - верстка адаптивная, благо tailwind позволяет (тестировал в хроме на маке)
   - ошибки и саксесс уведомления кое-где повыводил для наглядности, но не везде
   - добавил несколько компонентов для поиска, которые переиспользовал
   - не совсем понял какие статусы могут быть у выдачи, сделал на свое усмотрение
   - в модалке на создание/редактироване выдачи дизейблится поля книги и читателя, если необходимо
   - подобавлял софтделиты, так как в тз было указано удаление только из списка, а не из БД (в будущем полезно для истории/архива выдач)
   - при попытке удалить книгу, которая имеет хоть одну выдачу со статусом "выдано" вылазит ошибка
3. при генерации тестовых данных (сидер) в модели BookIssue может вылезти экспешин, так как связка полей book_id и user_id должна быть уникальны, ну а сидер на предыдущих итерациях может уже создать такую запись
4. модели Book и Author имеют связи many to many через пивотную таблицу поскольку у автора может быть несколько книг, как и у книги может быть не один автор
5. модель BookIssue имеет связи с Book и User (в качестве читателя)
